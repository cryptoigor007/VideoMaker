# Eval: эталонный набор сцен и протокол разметки

Этот каталог — отдельный eval-контур VideoMaker. Он **не меняет пайплайн** и
не участвует в рендере: только читает манифесты/библиотеку, собирает gold и
считает метрики. Production-рендер и приложение не перезапускаются.

```
eval/
  README.md          протокол разметки (этот файл)
  make_gold.py       сборка gold.jsonl из реальных манифестов + VLM top-N
  run_eval.py        метрики + report.md / report.json
  gold.jsonl         эталон (40 сцен, 30 train / 10 holdout)
  gold_meta.json     как собран gold: источники, VLM-вызовы, счётчики
  report.md          отчёт последнего прогона
  report.json        те же метрики машинно-читаемо
  common.py          split, метрики, JSONL (чистые функции)
  tests/test_eval.py pytest на синтетическом gold
  .cache/            копия БД, кадры VLM (в git не попадает)
```

## 1. Классы сцен

Класс отвечает на вопрос «что нужно показать в кадре», а не «какая это часть
сценария».

| Класс | Что это | Пример |
|---|---|---|
| `literal` | В речи есть конкретное действие/объект, и клип должен показать именно его. | «ты просыпаешься утром и чувствуешь усталость» → человек просыпается, садится на кровать. |
| `associative` | Прямого действия нет или оно метафорическое; нужен настроенческий/смысловой клип. | «ощущение, что рядом никого нет» → одинокий человек у окна; «вопрос меняется» → задумчивое лицо. |
| `abstract` | Визуального референта нет либо нужна графика/титр/цифры. | «И все.», «Кто-то пишет, вы общаетесь», сцены с графиками/таблицами. |

Класс в gold — **предварительный** (`class_confidence`, `class_signals`).
Человек может исправить класс, не меняя split.

## 2. Метки пригодности

| Метка | Значение | Что делать пайплайну |
|---|---|---|
| `accept` | Выбранный клип подходит сцене: действие/объект совпадает буквально или атмосфера точная и без противоречий. | Оставить. |
| `fallback_ok` | Выбранный клип не подходит, но в top-10 есть приемлемый кандидат (VLM ≥ 6/10) или, как минимум, literal-кандидат по метаданным. | Заменить на приемлемый клип; если он только по эвристике — проверить. |
| `must_graphic` | Пригодного клипа не подтверждено; для сцены лучше графика/титр, чем нерелевантный b-roll. | Графика/титр. |

`confidence` — уверенность в метке, 0..1. `needs_human_review=true` ставится,
если confidence < 0.7, нет VLM-оценки выбранного клипа, fallback подтверждён
только эвристикой или must_graphic поставлен не для abstract-сцены.

## 3. Поля gold.jsonl

Обязательные:

| Поле | Смысл |
|---|---|
| `scene_id` | `часть_01_123` / `часть_02_045` — уникален. |
| `scene_text` | Текст сцены из манифеста. |
| `class` | `literal` / `associative` / `abstract`. |
| `label` | `accept` / `fallback_ok` / `must_graphic`. |
| `confidence` | 0..1, уверенность в `label`. |
| `candidate_ids` | Top-10 кандидатов библиотеки в порядке ранжирования (id = имя файла). |
| `selected_clip` | Полный путь к клипу, который реально выбрал пайплайн. |
| `notes` | Почему такая метка: VLM-оценки, число приемлемых, эвристика. |
| `needs_human_review` | Булево: сцену надо посмотреть человеку. |

Дополнительные (нужны для метрик и разбора):

| Поле | Смысл |
|---|---|
| `candidate_scores` | VLM-балл кандидата или `null`, если не проверялся. |
| `candidate_meta` | `id, rank, file, db_score, vlm_score, vlm_what, literal_action, literal_match, literal_terms, acceptable, vlm_verified`. |
| `acceptable_ids` | Клипы, признанные приемлемыми: VLM ≥ 6/10 + выбранный, если он принят. |
| `recall_eligible` | `true`, если есть приемлемый клип **в библиотеке** и офлайн-Recall@K определён. Иначе сцена не входит в знаменатель recall. |
| `selected_id`, `selected_score`, `selected_what` | id/балл/описание выбранного клипа; балл — VLM из манифеста (`vlm_source=manifest_vlm`). |
| `selected_in_library` | Есть ли клип в индексе библиотеки. |
| `split` | `train` / `holdout`; фиксируется при сборке. |
| `part`, `scene_index`, `start`, `end` | Провенанс сцены. |
| `queries`, `visual`, `orientation`, `emotions`, `mood`, `shot`, `weights`, `avoid`, `hard` | Вход поиска; нужны для `run_eval.py --retrieval fresh`. |
| `class_confidence`, `class_signals` | Эвристика класса: действия/объекты/метафоры/графика. |
| `candidate_search_ms`, `vlm_calls` | Время поиска и распределённые VLM-вызовы при сборке. |
| `source_manifest` | Путь к исходному `smart_broll_manifest.json`. |

## 4. Как размечать вручную

1. Возьмите `eval/gold.jsonl`. Сначала смотрите строки с
   `needs_human_review=true`, затем все `holdout` (их всего 10).
2. Откройте `selected_clip` (QuickTime / `ffplay`) и прочитайте `scene_text`,
   `visual`, `queries`. Проверьте именно **действие и объект**, а не «красиво ли».
3. Поставьте метку:
   * `accept` — выбранный клип не противоречит сцене; для literal-сцены
     действие видно буквально;
   * `fallback_ok` — выбранный не подходит, но в `candidate_meta` есть клип,
     который подходит (посмотрите его; если VLM-балла нет — поставьте свой);
   * `must_graphic` — ни выбранный, ни кандидаты не годятся, либо сцена
     abstract и графика уместнее.
4. При необходимости исправьте `class` и `confidence`. Для `accept`
   обычно 0.85–0.95; для `fallback_ok` 0.7–0.85; для `must_graphic` 0.7–0.9;
   сомнительные — 0.4–0.6.
5. Поставьте `needs_human_review=false` и добавьте поля
   `"review_note": "..."`, `"reviewer": "имя"`, `"reviewed_at": "2026-..."`.
   **Не меняйте** `scene_id`, `candidate_ids`, `acceptable_ids`, `split`:
   иначе поедет воспроизводимость.
6. Holdout (10 сцен) — только для финальной проверки. Не подбирайте пороги,
   промпты и правила по holdout; для этого есть train.

Если меняете `acceptable_ids` вручную, пересчитайте `recall_eligible`:
достаточно, чтобы хотя бы один id был из библиотеки.

## 5. Как собрать gold

```bash
cd /Users/dreamstore/VideoMaker-r57cp34
.venv/bin/python3 eval/make_gold.py --limit 40 --verify-top 3 --candidates 10
```

Что происходит:

* в исходных папках `scenes.jsonl` не было (baseline-логи не сохранились),
  поэтому сцены берутся из `smart_broll_manifest.json` частей 1–2 (442 сцены),
  а кандидаты оцениваются через `verify.py`;
* выбранный клип ищется через `library_file`/`files` и индекс
  `~/video_maker/broll_library.db` (клипы, которых нет в библиотеке,
  пропускаются — офлайн-recall по ним не измерить);
* сцены стратифицированно отбираются по классам: 16 literal / 20
  associative / 4 abstract (фактические квоты зависят от доступных данных);
* top-10 кандидатов достаются тем же `search_library_multi`, что в пайплайне,
  без stock-API и скачивания;
* top-3 кандидата каждой сцены проверяются `verify.py` (VLM, батчи по 5,
  порог 6/10); выбранный клип использует готовую VLM-оценку из манифеста;
* пишутся `eval/gold.jsonl` и `eval/gold_meta.json`.

Кэш VLM и копия БД — в `eval/.cache/`; production-база не мутируется.
`--verify-top 0` отключает новые VLM-вызовы. `--dry-run` показывает выборку
без записи. `--no-db-copy` использовать только осознанно (VLM-кэш пойдёт в
production).

## 6. Как прогнать метрики

```bash
# быстро: использует порядок кандидатов, сохранённый при сборке gold
.venv/bin/python3 eval/run_eval.py --retrieval gold

# честно: заново запускает поиск по текущей библиотеке (~10-15 мин)
.venv/bin/python3 eval/run_eval.py --retrieval fresh
```

Отчёт: `eval/report.md`, машинно-читаемо: `eval/report.json`.

Метрики:

* **Recall@1/3/10** — доля recall-сцен, где приемлемый клип попал в top-K.
  Считается overall, по train/holdout и по классам.
* **literal hit-rate@1/@10** — то же для literal-сцен.
* **fallback rate** — доля `fallback_ok` + `must_graphic` (выбранный клип
  не принят).
* **время по стадиям** — `candidate_search_ms` (сборка) или измеренный
  retrieval (fresh), мс/сцену.
* **VLM/сцену** — реальные вызовы Vision при сборке gold (сейчас 0.30:
  12 вызовов на 40 сцен, потому что большая часть top-3 попала в кэш/префильтр).

### Split

30 train / 10 holdout. Разделение детерминированное:
`sha256(seed:scene_id)`, стратифицировано по `class` **и** `label`, чтобы
accept не оказались все в одной половине. Split записан в gold и при
обычном прогоне не пересчитывается. Holdout нельзя использовать для
настройки; отчёт по нему — контрольный.

## 7. Тесты

```bash
.venv/bin/python3 -m compileall -q eval
.venv/bin/python3 -m pytest eval/tests -q
```

Тесты не ходят в БД/VLM: проверяют Recall@K, literal hit-rate, fallback rate,
исключение нерелевантных сцен из знаменателя, split 30/10, стратификацию и
детерминированность.

## 8. Ограничения

* 40 сцен, holdout всего 10 — широкие доверительные интервалы; это
  smoke/regression-набор, а не статистически мощный бенчмарк.
* Кандидаты — только библиотека. Stock-API/скачивание не вызываются;
  стоковые клипы в офлайн-recall не участвуют.
* VLM проверяет top-3; `Recall@10` — нижняя оценка (клип на ранге 4–10 мог
  не проверяться). `must_graphic` при неподтверждённом fallback — тоже
  предварительная метка.
* VLM-оценки выбранного клипа взяты из манифеста (это тот же VLM, но не
  независимая перепроверка). Во время сборки были 503 от Gemini, поэтому
  часть кандидатов осталась без оценки; такие сцены помечены
  `needs_human_review`.
* Классы — эвристика по тексту/visual/запросам, а не ручная разметка.
  Особенно спорны rhetorical-вопросы и портреты: смотрите `class_confidence`
  и `class_signals`.
* `Path.exists` в eval-процессе кэшируется по индексу БД (SMB-stat слишком
  медленный). Если файл удалён из библиотеки, поиск этого не заметит;
  VLM/ffmpeg заметит при извлечении кадров.
* Время retrieval сильно зависит от SMB-кэша и загрузки диска; сравнивайте
  только прогоны на одной машине.
