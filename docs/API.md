# Пульт VideoMaker — HTTP API (r57-api)

Запуск сборки и наблюдение за ней **без кликов по окну**: из браузера, с телефона,
из скриптов и из Orchestrator.

Пульт живёт внутри приложения: поднимается вместе с ним и умирает вместе с ним.
Очередь строго последовательная — один рендер за раз (иначе 8 ГБ памяти и диск
на 40 МБ/с не выдержат).

---

## 1. Как запустить

| Способ | Команда | Что получается |
|---|---|---|
| Обычный | двойной клик `start.command` | окно + пульт; адрес видно в блоке «Пульт» |
| Без окна | `start-headless.command` | окно скрыто, пульт и очередь работают в фоне |
| Вручную | `./start.command --headless --api-port 8765` | то же, с явным портом |
| Без пульта | `./start.command --no-api` | только окно, как раньше |

Файлы состояния:

| Файл | Что внутри |
|---|---|
| `~/video_maker/api.json` | порт, токен, доступ из сети, вебхук |
| `~/video_maker/queue.json` | очередь серий (переживает перезапуск) |
| `<папка вывода>/videomaker.log` | лог прогона |

Автозапуск при входе в систему (headless) — `launchctl`, файл
`~/Library/LaunchAgents/com.videomaker.pult.plist`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>com.videomaker.pult</string>
  <key>ProgramArguments</key>
  <array>
    <string>/Users/dreamstore/VideoMaker/start-headless.command</string>
  </array>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
  <key>StandardOutPath</key><string>/Users/dreamstore/video_maker/launchd.log</string>
  <key>StandardErrorPath</key><string>/Users/dreamstore/video_maker/launchd.err</string>
</dict></plist>
```

Включить: `launchctl load ~/Library/LaunchAgents/com.videomaker.pult.plist`
Выключить: `launchctl unload ~/Library/LaunchAgents/com.videomaker.pult.plist`

## 2. Адреса

| Откуда | Адрес |
|---|---|
| С этого Mac | ссылка из блока «Пульт» (старый формат содержит `?key=ТОКЕН`) |
| С телефона (в той же Wi-Fi) | ссылка из блока «Пульт» (старый формат содержит `?key=ТОКЕН`) |

Ссылка с `?key=` используется только для первоначальной передачи токена старой версии страницы. Новая страница сразу удаляет `key` из адресной строки браузера и отправляет токен в `X-Api-Key`; запросы API не дублируют токен в URL. Сервер маскирует legacy `key` в HTTP access-логах. Для интеграций используйте заголовок, так как URL-токены могут сохраняться внешними прокси или копироваться вручную.

Токен и готовые ссылки показывает блок «Пульт» в окне и `GET /api/config`.
Чтобы открыть доступ из сети — галочка **«Доступ из локальной сети»** в окне
или `POST /api/config {"lan": true}`.

Пока доступ из сети выключен, пульт слушает **только 127.0.0.1**: снаружи порт
даже не открыт (не «403», а «нет соединения»). Включение сети перезапускает
сервер на `0.0.0.0` тем же портом; токен не меняется.

Страница пульта: статус, прогресс, стадия, «что идёт сейчас», очередь, логи.
Отдельный вид для встраивания в чужую панель: `GET /embed`.

## 3. Авторизация

Токен передаётся любым из способов:

```
X-Api-Key: <токен>
Authorization: Bearer <токен>
X-Webapp-Key: <токен>      # как в панели Orchestrator
X-N8N-Token: <токен>       # как в n8n-движке Orchestrator
?key=<токен>               # устаревший bootstrap, только для совместимости
```

Без токена — `403`. Запросы не с localhost отклоняются, пока не включён `lan`.
Исключения (доступны без токена): `GET /`, `GET /embed`, `GET /api/health`,
`GET /api/openapi.json`.

## 4. Ограничения запросов и безопасности

- Тело JSON — только объект до 2 MiB. Некорректное UTF-8/JSON, массив/скаляр в корне и неверный `Content-Length` дают HTTP 400; превышение лимита — HTTP 413.
- `lan` и `enabled` в `POST /api/config` должны быть настоящими JSON boolean. Строка `"false"` не может включить LAN. При повреждённом файле `api.json` невалидная настройка сети сбрасывается в безопасное состояние.
- Токен в query оставлен для старых клиентов, но новая веб-страница удаляет его из адресной строки и использует `X-Api-Key`; сервер редактирует секретные query-параметры в access-логах. В логах приложения также не печатаются ссылки, содержащие основной API-токен.
- HTTP остаётся незашифрованным. Используйте LAN только в доверенной сети и удалённый доступ через VPN; не пробрасывайте порт в публичный интернет.

## 5. Эндпоинты

### Состояние

| Метод | Адрес | Что отдаёт |
|---|---|---|
| GET | `/api/status?log_tail=30` | состояние, стадия, прогресс, прошло, осталось, что идёт, очередь |
| GET | `/api/job` | задача в формате панели Orchestrator (`{id,kind,title,total,done,percent,status,message,elapsed,eta}`) |
| GET | `/api/log?tail=200` | хвост лога |
| GET | `/api/log?since=<seq>` | только новые строки (для опроса) |
| GET | `/api/log/stream` | живой поток (Server-Sent Events) |
| GET | `/api/results?series=7` | что готово в папке серии |
| GET | `/api/health` | живость пульта: порт, доступ из сети, включён ли (без токена и секретов) |

### Управление

| Метод | Адрес | Тело | Что делает |
|---|---|---|---|
| POST | `/api/run` | `{}` или `{"audio":…,"output":…,"series":…}` | запустить сборку |
| POST | `/api/cancel` | — | остановить текущий прогон |
| GET | `/api/settings` | — | текущие настройки (секреты замаскированы) |
| GET | `/api/settings/schema` | — | схема формы настроек (секции, подписи, типы, варианты) |
| POST | `/api/settings` | `{"voice_enhance":true}` | изменить и сохранить настройки |

`POST /api/run` без тела запускает с тем, что стоит в окне. Перед стартом
настройки проверяются: если что-то не так — `400` и список причин, ничего не
запускается. Если прогон уже идёт — `409`.

Мусорные параметры (`?tail=abc`, `?since=abc`, `port: "abc"`) пульт не ломают:
берётся значение по умолчанию, а на бессмысленное тело приходит `400` с причиной.
Ответ `500` означает настоящий сбой, его причина пишется в лог.

### Ограничения и безопасность запросов

- Доступ из LAN выключен по умолчанию; включайте его только в доверенной сети.
- Токен принимается из `X-Api-Key`, `X-Webapp-Key`, `X-N8N-Token` или `Authorization: Bearer`; `?key=` оставлен только для совместимости.
- JSON-тело должно быть объектом не более 2 MiB. Некорректный JSON получает HTTP 400, слишком большое тело — HTTP 413.
- Ответы содержат `Referrer-Policy: no-referrer` и `X-Content-Type-Options: nosniff`.

### Что можно менять через API

`POST /api/settings` принимает **все поля, влияющие на сборку** (~90): пути,
флаги платформ, стили, модель Whisper, ключи Gemini, папки BGM, интро/середину/
аутро по форматам (вкл, файл, длительность), тексты и хештеги, обложки,
`target_lufs`, `voice_enhance`, паузы, скорость речи отдельно для длинного и
шортов, вырезку повторов, промпт. Полный список отдаёт `GET /api/settings`, а
`GET /api/settings/schema` — готовое описание формы (секции, подписи, типы,
варианты выбора) для веб-пульта и внешних панелей. Секреты отдаются как `***`;
отправка `***` обратно означает «не менять». `target_lufs` — конечное число в
диапазоне −36…−5 и применяется к финальному миксу с BGM; voice-only выдача не
запускает дополнительный loudnorm-проход ради скорости.

`remove_long_pauses` — необязательный булев флаг (по умолчанию `false`). При
`true` осторожно сокращаются только длинные межсловные паузы; короткие паузы и
более длинные паузы после знаков пунктуации в основном сохраняются. Тайминги
слов и субтитров пересчитываются после удаления тишины. Настройка доступна и
через галочку GUI «Сокращать длинные паузы между словами», и через API, например:

```json
{"remove_long_pauses": true}
```

Для основного конвейера целевой темп задан нижней границей — **120 слов/мин**;
ускорение применяется только когда речь выходит за выбранный диапазон. Если
сокращение пауз выключено, оригинальные паузы не вырезаются.

Особые случаи:

| Поле | Поведение |
|---|---|
| `series_name` | пишется в поле серии окна (Text-виджет), в переменную и в настройки |
| `add_bgm` | вычисляется приложением из `bgm_*_enable` — задавайте флаги платформ |
| `prompt_body`, `prompt_extra` | живут в текстовых полях окна: правка из API действует до следующего сохранения из окна |
| `gemini_api_key`, `gemini_api_keys` | задать можно; в ответах всегда `***` |
| пути Intro/Middle/Outro по форматам | только в окне (вкладка IMO), через API не меняются |

### Очередь (пакетная обработка)

| Метод | Адрес | Что делает |
|---|---|---|
| GET | `/api/queue` | вся очередь + текущая + счётчики |
| POST | `/api/queue` | `{"audio":"…","output":"…","series":"7"}` или `{"items":[…]}` |
| DELETE | `/api/queue/{id}` | убрать запись |
| POST | `/api/queue/{id}/retry` | повторить упавшую |
| POST | `/api/queue/pause` | `{"paused":true}` |
| POST | `/api/queue/clear` | убрать завершённые |

Следующая серия стартует сама, как только приложение освободилось. Успех
определяется по появлению выдачи (`info_metadata.txt` в папке серии), неудача —
по ошибке в логе. Статусы: `pending`, `running`, `done`, `failed`, `canceled`.

`audio` — файл или папка: папка раскладывается в очередь (файлы + один уровень
подпапок), и каждая серия получает свою папку в выдаче.

### Оркестрация и автоматизация

| Метод | Адрес | Что делает |
|---|---|---|
| POST | `/webhook/videomaker/render` | принять задачу, сразу вернуть `{id,url,state}` (формат n8n-движка) |
| GET | `/webhook/videomaker/render/{id}` | состояние задачи по id |
| GET | `/api/config` | адреса, токен, вебхук |
| POST | `/api/config` | `{"lan":true,"webhook_url":"https://…","port":8765}` |
| GET | `/api/openapi.json` | описание API для скриптов и агентов |

Вебхук: когда серия завершается, VideoMaker делает `POST` на `webhook_url`:

```json
{"event":"series_finished","status":"done","series":"7",
 "audio":"/path/7.m4a","output":"/path/out",
 "error":"","result":{"series_dir":"…","files":24,"total_bytes":123},"finished_at":"…"}
```

Запрос уходит с заголовком `X-Webhook-Token` — это отдельный секрет вебхука
(поле `webhook_token` в `~/video_maker/api.json`). Основной токен пульта в
исходящих запросах не передаётся.

## 6. Примеры

```bash
K=$(python3 -c "import json;print(json.load(open('$HOME/video_maker/api.json'))['token'])")
B=http://127.0.0.1:8765

# что сейчас происходит
curl -s -H "X-Api-Key: $K" $B/api/status | python3 -m json.tool

# запустить сборку с текущими настройками
curl -s -X POST -H "X-Api-Key: $K" $B/api/run

# запустить конкретную серию
curl -s -X POST -H "X-Api-Key: $K" -H "Content-Type: application/json" \
     -d '{"audio":"/Volumes/SSD/аудио/8.m4a","output":"/Volumes/SSD/выдача","series":"8"}' \
     $B/api/run

# поставить пачку серий на ночь
curl -s -X POST -H "X-Api-Key: $K" -H "Content-Type: application/json" \
     -d '{"items":[{"audio":"/аудио/8.m4a"},{"audio":"/аудио/9.m4a"},{"audio":"/аудио/10.m4a"}]}' \
     $B/api/queue

# живой лог
curl -N -H "X-Api-Key: $K" $B/api/log/stream
```

## 7. Встраивание в Orchestrator

VideoMaker отдаёт готовые файлы в формате, который Orchestrator **уже умеет
читать** (`docs/VIDEOMAKER_OUTPUT.md` в его репозитории): папка серии с
`info_metadata.txt`, `<платформа>/{wide,vertical}/final_*.mp4`,
`<платформа>/shorts/short_NNN/`. То есть публикация уже работает через
`watcher.scan()` — как только каталог виден с pve.

### Шаг 1. Сделать выдачу видимой для pve

Открытая задача в `orch-work/docs/HANDOFF.md`: расшарить
`/Volumes/SSD/untitled folder` на Mac по SMB и смонтировать на pve.
На Mac: «Системные настройки → Основные → Общий доступ → Общий доступ к файлам»,
добавить папку. На pve: смонтировать в `/mnt/video/...` (тогда путь
`.video_maker_settings.json` и путь pve сойдутся по правилу
`/Volumes/video/...` ↔ `/mnt/video/...`).

### Шаг 2. Запуск рендера (три варианта, от простого к глубокому)

**А. Без правок в Orchestrator** — встроить страницу пульта в панель:

```html
<iframe src="http://<IP-Mac>:8765/embed?key=<ТОКЕН>" width="100%" height="620"
        style="border:0;border-radius:12px"></iframe>
```

Панель сама покажет статус, прогресс, ETA, очередь и логи. Токен берётся из
`~/video_maker/api.json` (или из блока «Пульт» в окне).

**Б. Маленький клиент в Orchestrator** — рядом с `engines/n8n_engine.py`,
форма ответа уже совпадает с `N8nEngine`:

```python
# POST {videomaker}/webhook/videomaker/render
#   {"audio": "/mnt/video/audio/8.m4a", "series": "8"}  → {"id": "...", "state": "queued"}
# GET  {videomaker}/webhook/videomaker/render/{id}      → {"state": "running|done|failed"}
```

Опрос статуса для панели — `GET /api/job`: форма ровно как у `jobs.py`
(`{id,kind,title,total,done,percent,status,message,elapsed,eta}`), поэтому
существующий виджет прогресса подойдёт без переделки.

**В. Из n8n / скриптов** — тот же вебхук, заголовок `X-N8N-Token`.

### Шаг 3 (необязательно). Обратный вебхук

`POST /api/config {"webhook_url":"http://192.168.100.40:8080/webapp/api/..."}` —
Orchestrator узнает о завершении серии сразу, без опроса.

## 8. Безопасность

- Доступ из сети **выключен по умолчанию**, и до его включения порт слушает
  только `127.0.0.1` — снаружи соединение не устанавливается.
- Токен обязателен для всех `/api/*` (кроме `health` и `openapi.json`).
- Наружу в интернет пульт не выставлять: без порт-форвардинга, для удалённого
  доступа — VPN (у вас есть Tailscale).
- Токен лежит в `~/video_maker/api.json` с правами `600`.
- Пульт не публикует ничего и не удаляет файлы: только запускает сборку,
  меняет настройки приложения и читает состояние.

## 9. Если что-то не так

| Симптом | Причина и что делать |
|---|---|
| Страница открывается, данные не грузятся | Для старой ссылки скопируйте URL целиком из блока «Пульт»; после загрузки новая страница удаляет `key` из адресной строки и использует заголовок |
| `403 доступ из сети запрещён` | включите галочку «Доступ из локальной сети» |
| `403 нет токена` / `неверный токен` | токен изменился: смотрите `~/video_maker/api.json` |
| С телефона не открывается | Mac и телефон в разных сетях, или macOS блокирует входящие (разрешите во всплывшем окне файрвола) |
| `409 пайплайн уже выполняется` | идёт прогон; дождитесь или `POST /api/cancel` |
| `504 Tk-поток не ответил` | окно закрыто или занято модальным диалогом; в headless диалоги заменены логом |
| `403 доступ из сети запрещён` | соединение есть, но `lan: false` — включите галочку в окне |
| `400` на странные параметры | так и задумано: пульт объясняет причину вместо падения |
| Порт занят | `--api-port 8766` или поменяйте `port` в `api.json` |

## 10. Как это проверено

Две готовые проверки лежат в `tests/` (pytest их не собирает — это отдельные
инструменты):

```bash
# Проверка живого пульта: маршруты, авторизация, ошибки и сеть; нужен запущенный API
python tests/verify_api_live.py 8765 <токен> [IP-Mac]

# Проверка карты «настройка → переменная окна» (актуальный прогон: 70/70)
python tests/verify_api_settings.py

# Проверка блока «Пульт» в самом окне: подпись, галочка сети, кнопка (33/33)
python tests/verify_app_gui.py
```

Первая требует запущенного приложения, остальные — нет. Оконная проверка
идёт на настоящем `mainloop` — на `root.update()` межпоточные вызовы Tk ведут
себя иначе и результат был бы недостоверным.

## 11. Ограничения

- Пульт существует только пока живо приложение (headless — тоже приложение).
- Один рендер за раз: очередь последовательная намеренно.
- Скорость рендера пульт не меняет: узкое место — диск и кодирование.
- `POST /api/settings` меняет настройки **приложения**; часть из них применяется
  со следующего запуска (как и при правке в окне).
