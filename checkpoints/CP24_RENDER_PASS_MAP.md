# CP24 — карта проходов обработки и базовый замер

Дата: 2026-10-12. Это аудиторская карта кода CP23 перед оптимизацией. Время полного видео не заявляется без одинакового входа на целевом Mac; здесь измерены тесты и проверены статические маршруты кода.

## Порядок рабочего конвейера

GUI строит стадии строго в таком порядке: `AudioStage → TranscribeStage → GeminiStage → MasterBuilder → ParallelFinals → ShortsCutter → FinalizeStage`. Название `ParallelFinals` историческое: реализация намеренно работает последовательно `FinalHorizontal → FinalVertical`, чтобы не конкурировать за VideoToolbox/SSD.

## Дорогие операции по этапам

1. **AudioStage:** ffprobe длительности (кэшируемый запрос, не транскрипция/энкодинг).
2. **TranscribeStage:** один вызов транскрипции Whisper на исходный файл. `prepare_narration` делает 0 или 1 audio-only PCM WAV рендер: ноль, если не нужны обрезка, изменение темпа или включённое сокращение пауз; один, когда преобразование нужно. В этом снимке при `voice_enhance=True` далее ещё выполняется voice enhancement отдельно на выходах H и V (см. CP25, оптимизируем).
3. **GeminiStage:** один пакетный запрос анализа для текущего транскрипта (возможны штатные повторные попытки по ключам/сетевым ошибкам).
4. **MasterBuilder / horizontal:** один полный 4K H.264 encode, склейка B-roll на лету, синхронизация длительности и AAC narration в той же команде. Нет промежуточных `norm_*.mp4`.
5. **MasterBuilder / vertical:** если задана папка нативного вертикального B-roll — ещё один полный encode вертикального master с voice track; если выбран `vertical_background`, отдельный вертикальный master не строится, VSTACK откладывается в final branch.
6. **FinalHorizontal:** при включённом hook/subtitles/strong — один полный видео encode с ASS. Иначе отдельный burn проход отсутствует. Включённые Intro/Middle/Outro могут создать только короткие still→video сегменты (если выбраны изображения), потом быстрый concat/replace; при несовместимости кодеков fallback может быть дороже и отмечается в журнале.
7. **FinalVertical:** при native-vertical исходнике и включённом burn — один полный encode с ASS. При `vertical_background` геометрия 9:16 и ASS совмещены в один encode; второго geometry-only encode в штатном пути нет.
8. **ShortsCutter:** для каждого уникального клипа сначала stream-copy trim; VideoToolbox re-encode выполняется только как fallback, если контейнер/границы не прошли проверку. При включённом hook/subtitles/strong выполняется один полный video encode для конкретного шортса. Этот проход нужен, чтобы прожечь свой текст и тайминг клипа.
9. **FinalizeStage:** для каждой публикационной версии с BGM применяется микширование audio через FFmpeg с `-c:v copy` и AAC audio; это не video encode, но всё равно читает/перепаковывает видеопоток и создаёт файл. Идентичные Shorts (одинаковый source + байтово одинаковый selected BGM + совпадающие параметры) дедуплицируются. Различающиеся BGM-варианты оставляются разными по замыслу. Без BGM готовое видео размещается без дополнительного encode.

## Подтверждённая лишняя работа до CP25

При `voice_enhance=True` обе ветви H/V после сборки отдельно выполняли: extract audio from rendered MP4 → `voice_enhance_filter` → `replace_audio` обратно. Это три FFmpeg запуска на ветку, 6 на один выпуск, поверх обычного master/ASS. Обе ветви исходно используют одну и ту же narration, поэтому фильтр можно применять к общей PCM narration один раз до MasterBuilder, а полученный lossless WAV использовать для обеих ветвей. Это не убирает обязательный encode изображения H/V, но удаляет 4 лишние пострендерные FFmpeg операции из 6 и исключает повторную компрессию AAC в voice-enhancement этапе. CP25 реализует это с fallback для прямого вызова веток без TranscribeStage.

## Базовые проверки CP24

- `python -m compileall -q video_maker tests`: PASS.
- `python -m pytest tests/ -q`: **163 passed, 1 skipped, 23 subtests passed** (headless; пропущена одна display-only проверка Tk layout).
- Статическая карта основывается на текущих вызываемых стадиях, а не на названии класса. Отдельный end-to-end benchmark реальной много-минутной записи на Mac ещё требуется: Linux headless окружение не воспроизводит скорость Apple Silicon / VideoToolbox / MLX.

## Ограничения

- Не пытаться «параллелить» H/V без замеров Mac: текущая последовательность предотвращает конкуренцию за VideoToolbox и SSD.
- BGM для разных платформ/ассетов может быть разным, поэтому каждый различающийся микс остаётся отдельным. CP25 не будет склеивать различающиеся по музыке outputs.
- Нельзя пропускать финальный ASS encode, если hooks/subtitles/strong words включены — иначе функция существует только в настройке, но отсутствует в видео.
