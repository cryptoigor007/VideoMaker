# VideoMaker

Автоматическое создание длинных видео и Shorts из аудио + B-roll; встроенный HTTP-пульт для запуска, очереди, статуса и настроек.

**Текущая сборка: r57-api.14 (2026-10-12)** — CP24 документирует точное число проходов транскрипции/анализа/кодирования; CP23 улучшает адаптивный браузерный пульт; CP22 исправляет адаптивность desktop GUI: длинные настройки прокручиваются, основные действия закреплены, журнал и HTTP-пульт вынесены на отдельную вкладку, а окно настроек сохраняет видимую кнопку «Сохранить». CP17 добавил deadlines/атомарные аудиовыходы, CP18 уточнил область действия LUFS, CP19 укрепил HTTP API, CP20 исправил безопасность output-путей и кэшей. История и ревизии: [VERSION.md](VERSION.md), [CHANGES.md](CHANGES.md). Полный отчёт глубокого аудита: [AUDIT_DEEP_REVIEW.md](AUDIT_DEEP_REVIEW.md).

## Интерфейс (CP22)

- Главное окно подбирает размеры по разрешению экрана и центрируется вместо принудительного растягивания почти на всю высоту.
- Длинные настройки на вкладках «Основные» и «Intro / Middle / Outro» прокручиваются колёсиком мыши или полосой прокрутки; кнопки «Создать видео» и «Отмена» и прогресс остаются закреплёнными.
- На узких окнах поля B-roll и имя серии перестраиваются вертикально, чтобы поля выбора пути не сжимались до нечитаемой ширины.
- Журнал и сетевой пульт вынесены на вкладку «Журнал и пульт»: нижние элементы не исчезают под большим журналом на дисплеях с небольшой высотой.
- Окно настроек получило адаптивный размер; кнопка «Сохранить» закреплена отдельной нижней строкой. Большое тело промпта имеет собственную полосу прокрутки, а многострочные поля ключей/промпта используют тёмный контрастный стиль.
- Тесты раскладки запускаются с дисплеем: `xvfb-run -a pytest -q tests/test_gui_layout_cp22.py`. На машине без графического дисплея этот дополнительный UI-тест пропускается; основной набор backend-тестов от GUI не зависит.

## Карта проходов обработки (CP24)

См. [`checkpoints/CP24_RENDER_PASS_MAP.md`](checkpoints/CP24_RENDER_PASS_MAP.md). По умолчанию конвейер не запускает повторную транскрипцию или повторный анализ специально ради другого формата: Whisper/Gemini выполняются один раз на исходный ролик. Горизонтальный master кодируется один раз; вертикальный master кодируется отдельно только при нативном вертикальном B-roll. В режиме vertical-background геометрия и ASS совмещены в один encode. Каждый Shorts обрезается быстрым stream-copy и получает один отдельный encode только для собственного текста. Финальный BGM сохраняет видеопоток через `-c:v copy` и микширует/кодирует только аудио.

CP25 устраняет повторный `voice_enhance` на двух готовых MP4, перенося тот же фильтр на общую lossless narration-дорожку до мастеров. На синтетическом 8-секундном аудио число FFmpeg-вызовов именно этого подэтапа уменьшилось с 6 до 1; это не является заявлением о таком же ускорении всей серии. Полный реальный speed benchmark требует сравнить одинаковый источник и настройки на целевом Mac; headless CI не считается измерением скорости Apple Silicon/MLX.

## CP26 — проверка общего аудио мастеров

Горизонтальный и нативный вертикальный мастера должны использовать один `narration_enhanced_*.wav`, подготовленный до `MasterBuilder`. Если `voice_enhance_applied=True`, финальные ветви не запускают извлечение/повторное улучшение/подмену аудио. Старый fallback остаётся только для прямых интеграционных вызовов без готовой общей дорожки. BGM микшируется `FinalizeStage` для выбранных площадок; legacy BGM-флаг не запускает старую audio-post цепочку. Проверки описаны в `checkpoints/CP26_MASTER_PARITY.md`.

## CP27 — кэш метаданных BGM

При BGM-финализации один и тот же master/Short может быть источником для нескольких платформ. `verify_bgm_output` кэширует метаданные неизменённых файлов по canonical path, времени изменения, размеру и ffprobe binary. Источник больше не пробится отдельным процессом для каждой платформы, но каждый новый результат микширования остаётся независимо проверенным. Отчёт: `checkpoints/CP27_BGM_PROBE_CACHE.md`.

## Браузерный пульт (CP23)

- На широком экране блок статуса и очередь расположены в двух колонках; на телефоне блоки переходят в одну колонку без горизонтальной прокрутки.
- Поля очереди имеют доступные подписи, прогресс озвучивается как progressbar, действия повторить/удалить имеют область нажатия не менее 44×44 px.
- Контраст кнопок и вторичного текста повышен; клавиатурный фокус виден; обработано `prefers-reduced-motion`.
- Сохранены все операции пульта: запуск/отмена, добавление, пауза/продолжение, очистка завершённых, повтор и удаление задания, журнал. Режим `embed=1` сохраняет DOM-узел состояния для клиентского кода.
- Browser smoke (если Chromium + Playwright доступны): `python tests/verify_webui_visual_cp23.py`; тест работает с mock API и не запускает видеообработку. Скриншоты: `checkpoints/CP23_WEBUI_DESKTOP_1365x900.png` и `CP23_WEBUI_MOBILE_390x844.png`.

## Итоговый аудит (CP28)

Краткий итог медиа-проходов, безопасности subprocess и последней проверки см. `checkpoints/CP28_FINAL_AUDIT.md`. Исправления CP25–CP28 не добавляют полного видеопрохода: общая обработка голоса выполняется один раз до мастеров, BGM использует video stream copy, а repeated source ffprobe results кэшируются по пути/mtime/размеру. В API остаются известные ограничения: HTTP без TLS и нет rate limiting.

## Основные функции

- **Создание видео и Shorts** с горизонтальной и вертикальной версиями, субтитрами, хуками, CTA и обложками.
- **Сокращение повторных рендеров Shorts:** сравнивается содержимое исходного клипа и музыкальной дорожки, а не только пути файлов. Идентичная пара источник+BGM обрабатывается один раз; разные музыкальные версии остаются отдельными. Отчёт: `shorts_dedup_report.json`.
- **Темп речи:** общий целевой темп по умолчанию — 120 слов/мин (границы 120–150, если используется соответствующая настройка движка). Реальное ускорение ограничено настройками пайплайна.
- **Громкость:** `target_lufs` задаёт цель только для финального микса с фоновой музыкой (по умолчанию −14 LUFS, допустимо −36…−5). Voice-only результат не получает дополнительный проход нормализации, чтобы не замедлять обработку. Значение проверяется до рендера.
- **Необязательное сокращение длинных пауз:** настройка `Сокращать длинные паузы между словами` выключена по умолчанию. При включении сокращаются только подходящие длинные промежутки, интервалы после пунктуации сохраняются длиннее, а тайминги слов/субтитров пересчитываются. Если word-level разметка неполная, автоматическая вырезка пауз не применяется.
- **BGM для площадок:** отдельные флажки и источники музыки для YouTube, TikTok, Instagram, RuTube, VK, Facebook и «Другое». Одинаковые треки, скопированные в разные папки, распознаются по содержимому.
- **HTTP-пульт (r57):** запуск/отмена, состояние и прогресс, живой лог, очередь серий, настройки и webhook-интеграция. Очередь последовательная — один рендер за раз. См. [docs/API.md](docs/API.md).
- **Режим `--headless`:** скрывает основное окно, но приложение всё ещё использует Tk-цикл; это не независимый Unix daemon и в графической сессии без дисплея работать не будет.
- **Остановка с понятным кодом ошибки:** неверные CLI-аргументы и ошибка создания GUI не считаются успешным запуском.
- **Безопасность результатов и кэшей:** имена серий и ID площадок не могут использоваться как `..`-путь; существующие symlink-каталоги платформ отклоняются; cleanup удаляет только зарезервированный staging, не общий `_tmp` или пользовательскую `shorts/`.
- **Диагностические временные файлы:** при `keep_temp_files=True` сохраняются промежуточные файлы каждого Shorts; при выключенном флаге обычные временные файлы удаляются по завершении.
- **Восстановимые кэши:** JSON/PNG/MP4 кэши публикуются атомарно или проверяются перед reuse; повреждённый cache-entry не принимается только по размеру файла.

## Быстрый старт (macOS Apple Silicon)

**Первый запуск — без ручного создания виртуального окружения:** распакуйте папку проекта и дважды щёлкните `start.command`. Скрипт проверит Apple Silicon/macOS, найдёт совместимый нативный Python, создаст `.venv`, установит runtime-зависимости и `mlx-whisper`, проверит импорт модулей и bundled FFmpeg, затем запустит GUI. При следующих запусках повторная установка пропускается, если зависимости не изменились.

Если macOS заблокировала запуск `.command`, откройте Terminal в папке проекта и выполните:

```bash
chmod +x start.command start-headless.command setup.command doctor.command
./start.command
```

- `setup.command` — установить/восстановить среду отдельно; `setup.command --check-only` — только проверить уже установленную среду без изменений.
- `doctor.command` — read-only диагностика системы, Python, зависимостей и bundled FFmpeg. Содержимое `.env` скрипт не выводит.
- `start-headless.command` — запуск без видимого главного окна в активной macOS-графической сессии; это не Unix daemon.
- Runtime-пакеты описаны в `requirements-runtime.txt`; `requirements.txt` дополнительно включает тестовый инструмент `pytest`.

### Требования MLX Whisper

Для транскрипции нужен Mac с Apple Silicon, нативный ARM64 shell/Python и macOS 14 или новее. Установщик предпочитает Python 3.13/3.12 и пробует совместимые 3.14/3.11 варианты, если доступны. На Intel Mac, Linux или через Rosetta установщик остановится с объяснением: текущий движок транскрипции использует MLX.

При первом распознавании `mlx-whisper` может скачать модель `mlx-community/whisper-large-v3-turbo`; для этого требуется сеть и свободное место. Загрузка модели не включена в ZIP, чтобы архив не был многогигабайтным. Видеодвижок использует bundled FFmpeg из `imageio-ffmpeg`, но часть аудио- и checkpoint-проверок также требует системные `ffmpeg` и `ffprobe`. Если их нет, установщик автоматически вызывает `brew install ffmpeg` (или `brew reinstall ffmpeg`, если формула есть, но инструменты не запускаются). Сам Homebrew должен быть установлен заранее; `doctor.command` показывает состояние инструментов.

### Что нужно настроить в интерфейсе перед первым видео

Само приложение запускается без изменения исходного кода. Для выпуска ролика пользователь должен один раз выбрать аудиозапись, горизонтальный и вертикальный B-roll/фон, папку экспорта, а также ввести Gemini API key через настройки приложения. Если для площадки включена фоновая музыка, у неё должен быть выбран действительный источник; если нужен voice-only результат — отключите BGM для этой площадки. Это входные данные конкретного выпуска, а не доработка программы.

Ключи и пользовательские файлы не поставляются в архиве. Не добавляйте действующие токены в ZIP, отчёты или скриншоты.

## HTTP-пульт

Токен и готовые ссылки показывает блок «Пульт» в окне и `GET /api/config`.

| Откуда | Адрес |
|---|---|
| С этого Mac | `http://127.0.0.1:8765/?key=ТОКЕН` |
| С телефона в той же Wi-Fi-сети | `http://<IP-Mac>:8765/?key=ТОКЕН` |

Пока доступ из локальной сети выключен, порт слушает только `127.0.0.1`. Включается переключателем «Доступ из локальной сети» или соответствующим API. Используйте токен; не пересылайте его вместе с публичными ссылками. Встроенный интерфейс для внешней панели: `GET /embed`.

## Требования

- macOS с рабочей графической сессией для GUI и `--headless`.
- **Для MLX Whisper:** Apple Silicon, нативный Python ARM64 `>=3.10`, macOS `>=14.0` согласно документации MLX. Это требование нельзя корректно описывать как macOS 10.13+.
- Python `>=3.10` для базовых модулей приложения.
- FFmpeg (`brew install ffmpeg`).
- `mlx-whisper` устанавливается отдельно для транскрипции на Apple Silicon.
- Достаточный свободный диск для B-roll, промежуточных MP4 и финальных файлов; для ускорения не сохраняйте временные файлы без необходимости.

### Проверки безопасности API (CP19)

- Query-токен сохранён только для совместимости и маскируется в access-логах; страница удаляет его из адресной строки после начальной загрузки и использует `X-Api-Key`.
- JSON-запросы ограничены 2 MiB, некорректные/необъектные JSON и неверный `Content-Length` отклоняются с 400, oversized — с 413.
- Ответы задают `Referrer-Policy: no-referrer` и `X-Content-Type-Options: nosniff`.

### Проверки безопасности API (CP19)

- Основной токен не печатается стартовыми логами; legacy query-secret редактируется в HTTP access logs и в логируемых webhook URL.
- Встроенная webui очищает `?key=` из адресной строки после получения токена и далее использует только `X-Api-Key`. Заголовочные credentials имеют приоритет над legacy query-параметром.
- `POST /api/*` ограничивает JSON-тело 2 MiB и возвращает 400/413 для некорректного/слишком большого запроса. В config нельзя передать строковое `"false"` и этим включить LAN; некорректные сохранённые значения приводятся к безопасному состоянию.
- Протестированы socket-level запросы к изолированному HTTP-пульту; весь набор: 149 passed + 23 subtests. См. `checkpoints/CP19_API_SECURITY.md`.
